# DGFlow Lab 当前实现协议

本文件描述提交代码实际执行的研究协议。算法基础来自《DGFlow: Privacy-Preserving and Robust Cross-Silo Federated Learning in Decentralized Cloud-Edge》，并结合 `proof-construction.md` 中明确给出的证明关系完成工程重建。不是原作者源码，不把实验原型等同于通过认证的密码产品。

## 修订记录

### 2026-10-08：当前拓扑、验证信任边界与规范编码

正文已按当前代码统一为可配置的 n/w/v、s/w 与 e/v、单归属原始证明核验和规范二进制编码。文件名 `protocol-v1.md` 为历史路径；下列带日期的修订记录保留当时配置和实测，固定人数及旧计时只描述对应历史版本，不能覆盖当前正文。

当前部署的每个客户端只有一个归属边缘。归属边缘核验原始证明并解出内积，其他边缘验证其签名、身份、上下文和归属，再独立筛选同一候选集合。其他边缘不重新核验被归属边缘持有的原始证明，因而验证正确性依赖归属边缘可信或半诚实；s/w 密钥保密门限不提供原始证明的多方独立复核保证。完整恶意边缘容错及组合安全归约仍未实现。

### 2026-10-04：原生完整核验、受检点复用和批量授权

匹配的新原生构建提供 `LegoVerifier.verify_linked`：一次调用完成原始 Lego 数值 SNARK、全部密文/注册密钥关联方程和共享见证开口。规范编码、曲线子群和标量检查仍执行；确定性模式逐方程核对，随机模式在受检解码后生成新鲜独立权重，失败时逐方程复核。旧原生构建保留原 Python 组合核验路径。

通过核验的密文点仅由本地不透明 `VerifiedLego` 句柄传给同一作业的授权内积。句柄绑定完整上下文、客户端、CRS、范数与密文字节，不能从网络输入、Python 构造或序列化生成；不缓存跨调用的验证结论。默认确定性核验，Lego 的 `verification_threads=2` 限制每个 authority 的原生计算线程预算，可设 1–4。实际公共验证进程数不超过该预算，每进程原生线程数取预算除以进程数的整数部分；操作系统辅助线程不计作原生计算线程。

三个 authority 全部经认证报告支持批量接口时，验证函数钥请求从 18 次合为 3 次，三云聚合函数钥请求从 9 次合为 3 次。每份函数钥保留原有身份和上下文绑定；聚合钥与正确性证书仍分别密封给指定云。集合或接收者不合法时拒绝整个批次，不允许通过接口改写参考向量。任一节点缺少能力时使用原单项接口。授权及结束确认仍等待三个 authority 独立核验。

聚合正确性证明的固定公开底数 `T=e(hash_point(ctx),G2)` 按完整上下文缓存；通过 `T^s` 计算与原配对等价。`combine` 在本次调用内复用通过全部证明检查的 GT 点，并先求 DKG 多项式系数群和再评价各 authority；不复用跨请求证明结果或信任根。新分项计时见[优化验收报告](../research/validation-authorization-optimization-20261004.md)。

### 2026-10-04：授权筛选和幸存成员策略

新建实验任务显式固定 `min_cosine=0`、`max_norm_ratio=2`、可选 `max_norm_squared` 与 `batch_strategy=regroup`。鲁棒模式先对经过密码证明的平方范数和余弦分数应用门限，再执行原二均值规则；范数比采用候选群体的下中位数，比较平方范数时门限取比值平方。配置持久绑定任务并写入共同签名的清单，不能在后续轮次改变。历史任务未指定这些字段时保留原筛选和固定批次语义。

`regroup` 把通过筛选的幸存成员汇入一个至少两人的授权组，奇数人数也全部保留，避免因一个异常或缺席成员排除其诚实伙伴。仅剩一人时拒绝发布单人聚合；`fixed` 可用于复现原固定两人批次对照。

### 2026-10-04：可验证部分解密

聚合钥新增以原 DKG 承诺为根的 Pedersen 多项式承诺和配对像正确性证明。authority 签名证书先随聚合钥密封到指定云，在云发布部分结果时公开。coordinator 和各 authority 均校验其证明、重算预期 E，并由批准密文重算 D；仅有合法云签名而 E 被篡改的结果不能再合并。旧部分结果缺少证明时拒绝。方程、身份信任链和边界见[证明规格第 17 节](proof-construction.md#17-2026-10-04部分解密正确性证明)。

### 2026-10-03：加速至 5B（可选实验套件）

新增 `compact_range_v1` 和 `compact_norm_v1`，关系及组合转录见 [证明规格第 13 节](proof-construction.md)。默认 `legacy` 保留逐位证明；紧凑套件需在任务创建时显式选定，并由上下文固定 `proof_suite` 和 `proof_block_size`。这些字段改变加密底数和证明摘要，所以不同套件之间比较的是整数结果，不比较密文或模型哈希以外的密码对象。

执行方式 `execution=serial|parallel|auto` 独立于模式；2026-10-06 起 `auto` 对所有模式使用有界并行，`serial` 保留显式串行对照。`rpc_workers` 限制复用的请求池，`verification_workers` 限制各 authority 的公共验证进程。`verification=randomized` 的误接受界限见证明规格第 14 节。原生 GT 扩展保留编码和子群检查；未安装时功能回退。请求与响应的大包传输均以认证块落盘并验证整体摘要，证明对象尚未完全流式化。DKG 按任务复用；每轮上下文、模型及授权仍独立绑定，筛选与所选固定或重组批次继续执行。

### 线格式修订（协议 v2），算法不变

**未变**：全部密码方程（`ct=f^s·g^x`、`VKGen`、`DKGen`、`AggDec`、`AggComb`）、8 位范围与平方范数证明的关系、门限（2/3）、固定批次、量化规格（scale=128、bits=8）、筛选规则。因此同一配置下的**整数模型与聚合结果完全相同**：d=650 优化模式单轮实测，修订前后准确率均为 0.44、参考平方范数均为 2530、获准客户端均为 6 个。

**已变（不向后兼容）**：

1. **编码**：G1/G2/标量/GT 由固定长度十六进制字符串改为原始字节（48/96/32/576 字节）；载荷由十六进制 JSON 改为自定义紧凑二进制编码。
2. **哈希域**：`digest`、`hash_point`、`challenge` 改为对二进制编码取摘要。所有上下文/清单/证明摘要、加密底数 `f` 与 Fiat–Shamir 挑战随之改变，因此**修订前后的运行记录不能做哈希级对比**，旧密文与旧证明也不再兼容。
3. **信封**：由 JSON 对象改为二进制帧，信封头同时作为 AEAD 关联数据。
4. **本地状态**：rpc-cache 与客户端提交标记由 `.json` 改为 `.bin`；旧文件不迁移，新建任务即可。

**新增能力**（修订前不存在，属于功能而非优化）：

1. **分块传输**：超过 24 MiB 的请求按 8 MiB 切块并绑定整体摘要，解除单条 64 MiB 对请求规模的限制。
2. **维度可配**：池化网格 `grid` 2–28，模型维度为 `10(grid²+1)`；默认 `grid=8`（650 坐标），`grid=28` 为全分辨率 7,850 坐标。

**实测**：单客户端封装体积 11,450 → 2,998 B/坐标（3.82×）；同配置单轮 `bytes_sent` 304,749,105 → 70,027,182（4.35×），耗时 167.4 → 112.5 s。7,850 维单轮真实运行完成，`authorize` 请求 134.6 MiB 被切成 17 块传输。

## 一、角色与信任边界

n 个客户端 `client1..clientN` 保存各自数据分区；w 个 `authority` 节点共同建钥，各自核验归属客户端并共同筛选、签发聚合许可；v 个 `aggregator` 节点分别产生部分解密；一个 coordinator 调度、转发消息并展示公开结果。新部署默认 n=6、w=3、v=4、s=2、e=2，已有部署重启时保留原拓扑。客户端之间和云节点之间没有协议通信，逻辑边缘协作由主控转发；不能把图中分层解释成已消除主控依赖。验证功能和密钥管理位于同一 authority 信任边界。

安全模式的 coordinator 不接收客户端个体明文向量，不持有 authority 私有份额，也不能打开客户端/聚合节点的角色密封消息。明文模式是明确登记的实验基线。新任务及初始参考模型由可信的本机实验管理员选择；本实现不提供对恶意管理员任意注册新任务和跨任务查询的隐私保证。已登记安全任务不能在训练阶段降级为明文模式。

固定成员采用认证信道；DKG 遇到不一致即中止。新建任务的密钥周期须全部 w 个 authority 在线并确认同一转录，之后在该任务内摊销复用。边缘份额恢复门限为 s/w，云聚合门限为 e/v；允许 n=2–100、w/v=2–32、s=2–w、e=2–v。当前轮次编排仍收齐全部边缘的授权与结束确认。部分解密另有强制正确性证明；错误结果会被拒绝并中止该轮，尚未提供自动选择诚实子集或拜占庭共识。单个边缘已完成而其他边缘结束失败时任务中止，不提供原密码轮次续跑。门限不保证任意一个物理主机失效都可继续。

## 二、参数与模型编码

| 项目 | 实现值 |
|---|---|
| 配对群 | BLS12-381 的 G1、G2、GT 素数阶子群 |
| 标量阶 q | `0x73eda753299d7d483339d80809a1d80553bda402fffe5bfeffffffff00000001` |
| 后端 | `py-arkworks-bls12381==0.5.0`；匹配的自研 Rust 原生扩展可选，Lego 套件必须具备该扩展及匹配 CRS |
| 本地模型 | MNIST 或 CIFAR-10 池化线性 softmax 分类器；完整 CNN 本地模块尚未接入安全联邦服务 |
| 网格与规模 | MNIST `grid=2–28`，默认 8 为 **650** 坐标，最大 **7,850**；CIFAR-10 `grid=2–25`，默认 8 为 **1,930**，最大 **18,760** |
| 坐标次序 | `channels×grid²×10` 权重按 C 顺序展开，后接 10 个偏置，共 `10(channels×grid²+1)` 个参数；MNIST/CIFAR-10 分别为 1/3 通道 |
| 量化 | 先剪裁至可表示范围，再 `numpy.rint` 舍入，正好半整数向偶数舍入 |
| 尺度/位宽 | scale=128，bits=8，整数范围 [-128,127] |
| 参与者 | n=2–100、w/v=2–32；实际数量与归属映射由部署解析并固定到任务 |
| 门限 | s=2–w、e=2–v；新默认均为 2，初始化及关键轮次仍要求全部边缘参与 |
| 成员分组 | 新实验默认 `regroup`，幸存成员至少两人共同聚合；`fixed` 按连续客户端编号配对，奇数末尾成员无伙伴时排除 |
| 聚合 | 获准客户端等权平均，平均后再次按同规格量化 |

输入是本地训练后的完整模型，全部坐标都进入密码链路；协议当前上限为 20,000 坐标，并另做消息大小下界预检。通过预检不证明 RAM/VRAM 足够或最大拓扑已实测。浮点剪裁/量化是公开的训练处理；密码证明验证的是剪裁量化后的整数，不证明原始浮点模型未超界。

令 B=128、维度 d≤20,000、实际获准客户端数 N≤100。平方范数上界为 `d·B²`（d=650 时 10,649,600；d=18,760 时 307,363,840）；最宽参考内积区间为 `[-d·B², d·B²]`。实现进一步取 `B*sum(abs(reference))` 与由已证明范数得出的整数 Cauchy–Schwarz 界的较小值。聚合坐标区间为 `[-NB,N(B-1)]`，N=100 时为 [-12,800,12,700]。这些范围远小于 q，不发生整数解释的模回绕。使用真实群上的 baby-step giant-step 有界离散对数恢复结果，查找表只含公开基点的幂，不保存客户端明文答案。

## 三、轮次上下文

共同上下文包括 task_id、round_id、key_epoch、model_hash、bits、scale、dimension，以及已选证明套件、模型与拓扑信息。密码消息、摘要与挑战使用 `transport/binary.py` 的规范 `packb` 编码：字典键按 UTF-8 字节排序，列表保持顺序，点和标量为受检原始字节，拒绝非规范表示。`digest` 是 `SHA-256(packb(value))`；`hash_point` 对同一规范编码执行带独立域的 hash-to-curve；Fiat–Shamir 挑战为 `SHA-512(b'DGFL_NIZK_V1\x00' + packb(transcript))` 按大端解释后模 q。JSON 仅用于明确的本地记录，不参与当前密码转录编码。

同一轮所有客户端使用共同 hash-to-curve 底数 f，client_id 不加入 f 的输入。身份在已登记密钥行、证明转录和通信封装中单独绑定。不同用途的 Pedersen 基点和加密底数使用不同域分离字符串。Pedersen 盲化基点通过 hash-to-curve 导出，不使用公开标量乘生成元的方式构造。

任务策略持久固定 mode、成员及顺序、batch_size、bits、scale、dimension，以及显式指定的相似度/范数门限和 batch_strategy。authority 在完成一轮后独立计算下一轮参考，下一轮请求必须一致。客户端按 task_id/round_id/client_id 保存不可变提交；换 epoch、参考或训练请求内容不能绕过业务去重。节点在耗时计算前记录 pending，意外中断后拒绝同轮重新生成另一份模型，要求创建新任务。

## 四、算法与实现对应

采用加法记号描述 G1/G2。G 为 G1 生成元，H 为未知离散对数关系的盲化基点，G2 为配对第二群生成元。

1. **GlobalSetup**：建立群、域分离、编码和界限。外部 G1/G2/GT 编码须通过规范编码及素数阶子群检查。Lego 额外使用任务固定的本地可信 CRS，单方开发设置不等同于多方仪式。
2. **AuthSetup**：每个 authority 对每个客户端坐标独立产生次数为 `s−1` 的秘密多项式与盲化多项式，公开 Pedersen 系数承诺。对其他 authority 的份额通过角色密封信道发送。接收者逐项检查承诺，全部 w 个边缘确认同一转录后相加得到自身份额并清除 dealer 多项式。
3. **EKGen**：每个客户端只收到自己密钥行的门限份额，恢复 s_ij、k_ij，并检查 `K_ij=G*s_ij+H*k_ij`。不发送其他客户端的行。
4. **Encrypt**：`ct_ij=f*s_ij+G*x_ij`。客户端同时公开整数平方范数 Xi，并生成绑定已确认 K、ct、上下文与 Xi 的范围/平方关系证明。
5. **VKGen**：authority 只对本轮固定参考 z 产生客户端内积函数钥份额，拒绝请求方另选向量。函数钥带节点签名和上下文摘要。
6. **VerDec**：利用配对消去加密掩码，得到公开 GT 基点的 `<x_i,z>` 次幂，再以有界离散对数解出整数内积。
7. **筛选及许可**：归属边缘核验客户端原始证明并执行 VerDec，签名共享证明有效性、余弦、范数、摘要及密文核心。其他边缘核对归属、签名和上下文，信任归属边缘的验证结论，独立执行任务固定的范数/相似度门限、二均值筛选与分组。签名证书绑定上下文、批准客户端、密文摘要、分组规则、筛选配置、拓扑与验证结果。当前编排要求全部 w 个边缘产生一致授权；只有不带部署拓扑的旧孤立测试保留全量原始证明核验路径。
8. **DKGen**：authority 仅对其本轮已签发的清单生成聚合函数钥；次数为 `e−1` 的新鲜随机多项式使不同 aggregator 获得各自份额，份额密封到对应 aggregator 身份。
9. **AggDec/AggComb**：aggregator 校验许可和密文摘要后产生带签名的 GT 部分结果，并公开随私有聚合钥取得的 authority 签名正确性证明。至少 e 个不同聚合节点的结果，经上下文/清单、DKG 承诺与配对像证明检查，以及从批准密文重算公共分子 D 后，才执行拉格朗日插值和有界离散对数。coordinator 及全部 authority 分别计算下一轮参考并核对一致。

G1/G2 以压缩点原始字节（48/96 字节）参与规范二进制编码，不再使用十六进制字符串。后端 Python 绑定缺少 GT 字节反序列化，本实现以 Fp12 的线性基还原原生字段元素，随后核对重新编码、非零与 q 阶子群条件；没有使用 pickle 或保存明文来替代 GT 解码。细节与负面测试见 `backend.py`、`tests/crypto/test_backend.py`。

## 五、证明关系

范围证明将每个 x+128 写成 8 位，并用 Pedersen 位承诺和 Schnorr OR 证明每位为 0 或 1。数值承诺由这些位承诺唯一重构。联合表示证明用同一个响应连接密文中的 x、数值承诺中的 x、平方关系中的 x，并用另一共享响应连接密文的 s 与实际发放密钥承诺。所有平方承诺之和打开为公开 Xi。

完整方程、见证、挑战、负数解释及安全边界见同目录 `proof-construction.md`。实现转录直接绑定上下文、客户端、实际 public_keys、密文、范数、所有首消息与总盲化量；DKG 转录由 authority 的已确认状态绑定，未额外把整个 DKG 转录重复塞入每个证明。此处是实现规格对较早草案的明确化。

此组合完成方程核对和篡改测试；没有宣称新的完整组合安全归约或外部专家审查已完成。范数证明不证明训练诚实，不证明没有投毒，也不隐藏系统主动授权的范数和内积。

## 六、鲁棒规则及实验消融

一维二均值以最小/最大分数初始化，最多迭代 32 次；只有两个中心之差≥0.45 且低中心<0.25 才排除低簇。这是本作品补充的固定工程规则，不声称由原论文逐字给出，也不随测试种子调整。全相同分数不会被强行拆成两组。鲁棒模式对零范数及不能解释的内积明确拒绝。

新实验在聚类前应用独立的平方范数绝对上限（可选）、L2 范数相对门限（默认群体下中位数的 2 倍）和余弦下限（默认 0）。这些规则可以排除同方向幅度放大，但相对门限依赖候选群体诚实多数，需要根据正常分布校准；绝对门限应由实验管理员按模型规模设定。合法、同方向且范数正常的恶意训练或标签翻转仍可能通过。证明保证数值关系，不证明标签正确或训练诚实；旧标签翻转通过的实验保留为该边界的证据。

| 模式 | 加密、范围/范数证明 | 投毒相似度筛选 | 调度与传输 |
|---|---|---|---|
| plain | 无，个体模型送达主控，界面明确标识 | 无 | execution 独立指定，auto 为有界并行 |
| encrypted | 有；合法零向量也可进入完整批次 | 无 | execution 独立指定，auto 为有界并行 |
| dgflow | 有 | 有 | execution 独立指定，auto 为有界并行 |
| optimized | 与 dgflow 相同 | 与 dgflow 相同 | execution 独立指定；支持时采用紧凑聚合材料 |

安全模式均由归属 authority 对原始完整证明核验，单归属分工与模式名称无关。证明摘要替代聚合节点不需要收到的完整证明，证书绑定相同的 submission_core 摘要。模式对照需要显式固定模型、定点编码、数据分区、种子、批次和执行参数；仅凭 dgflow/optimized 名称不能推导并行度或加速比。

## 七、通信与失败语义

节点 API 为 `/rpc`，由 HTTPS 双向证书认证保护。请求和响应使用**规范二进制信封**：`MAGIC|version|sender|recipient|purpose|context|nonce|ciphertext_len|ciphertext|signature`，由 Ed25519 签名、X25519/HKDF 派生、AES-GCM 密封并绑定发送者、接收者、用途和请求上下文；信封头同时作为 AEAD 的关联数据。载荷使用自定义紧凑二进制编码（见 `transport/binary.py`），曲线点按原始字节传输：密文与证明中的每个 G1 点为 48 字节，标量为 32 字节。相比此前的十六进制 JSON，实测单客户端提交从 11,450 B/坐标降到 2,998 B/坐标（3.82×）。禁止网络反序列化 pickle。

单条 RPC 正文上限 64 MiB。超过发送阈值（24 MiB）的请求由客户端自动切分为 8 MiB 的块，编号后以 `_chunk` 动作逐条发送；每块绑定**目标动作、块序号/总数与整体提交的 SHA-256 摘要**，该摘要覆盖完整的 `{action,payload}` 编码，因此任务、轮次、密钥周期、模型摘要、客户端、维度与坐标范围一并绑定。节点按 `(发送者, 摘要)` 缓冲并拒绝：块序号越界、同序号改写、块总数或目标动作中途变更、缺块、截断、整体摘要不符、超出发送者并发数与总字节上限。只有完整装配且摘要吻合后才执行目标动作并签发结果；单个块的精确重试命中幂等缓存。

大回复由已认证的清单和 `_download` 分块获取，完整逻辑消息上限仍为 1 GiB。2026-10-08 起新节点返回 v2 回复清单；客户端为每次下载创建独立会话，全部块、整体摘要和解码均成功后发送绑定原请求、摘要与会话的 `_download_complete` 确认。节点只在容量不足时按最近访问顺序回收全部会话均已确认完成的回复；未完成或已发出重试清单但尚未开始下载的回复继续占槽，最多 16 份、磁盘预算 16 GiB，闲置 900 秒过期。回收不删除独立业务执行记录，缓存仍在时精确重试返回原结果，回收或过期后拒绝重新获取并且不重新执行业务动作。确认通信失败时客户端仍返回已完整验证的结果，服务保留回复至过期或后续完成确认。

新版客户端可读取旧 v1 清单并保留原 TTL 行为；旧客户端不支持新 v2 清单，因此启用该容量修复须同步更新并重启主控和全部角色。更换代码不要求重建身份、CRS 或历史记录。

角色消息虽可由 coordinator 转发，其内部秘密仍密封到最终角色。浏览器只访问本机控制面，不能通过浏览器 API 读取节点私有文件。控制服务默认仅绑定回环地址；三机场景只有角色端口需要内网访问。

相同 RPC 请求 ID 返回原业务响应，不同内容复用 ID 被拒绝。业务提交另有持久唯一键，不能靠换 RPC ID 重复训练。健康探测是只读接口，不逐次落盘，避免长期运行产生无界心跳缓存。每轮客户端调用超时或无法返回时按缺席处理；regroup 保留其他合格成员，fixed 使缺席成员的固定伙伴连带退出。相同加密请求的网络重试使用原请求信封。

本机初始化、启动、停止和拓扑重配由运行目录级 `lifecycle.lock` 的操作系统排他锁保护；同线程内部事务可重入，竞争操作在修改 PID 前明确拒绝。控制服务的长期锁独立保留，`demo` 在初始化和启动角色前取得控制服务锁。锁文件持久保留，不能在进程运行中删除；进程退出或崩溃由操作系统释放锁。不同运行目录相互独立。

实际离线检测来自 mTLS 健康调用和实际 RPC 返回。界面中的“本轮排除聚合节点”是实验配置排除，与真实停止进程不同。聚合不足 e 个结果、没有完整合格批次、上下文不一致、解码越界等情况停止该轮并保留错误，不能显示成功模型。节点重启后不尝试恢复未持久化的秘密 DKG 状态；创建新任务、新周期，保留已完成历史。

## 八、与初步计划的实施差异

采用原生 Windows arkworks 绑定而非尚未验证的 Charm/WSL 路线；默认真实训练为 NumPy，torch CPU 是可选适配。以原子 JSON/二进制记录、节点串行锁和业务唯一键完成持久状态，不引入 SQLite。数据由每个客户端从公开 MNIST 或 CIFAR-10 本地缓存划分；本演示不代表机构间真实数据权限隔离。角色 RPC 采用认证密封的规范二进制而非 multipart，界面 RECEIVED 来自客户端调用实际完成事件。上述差异以可运行性、角色隔离和可审计性为目的，不改变“完整模型实际进入密码链路”的验收目标。
