# 架构对比：当前项目与指导论文

更新：2026-10-11。依据[论文](../DGFlow-指导论文.pdf)与当前源码；不使用历史行数、默认值或完成度百分比作为当前结论。详细实验与差距见[论文差距分析](paper-gap-analysis.md)。旧全文的逐字快照保存于[历史审计目录](../../tmp/attack-defense-audit-20261011/paper/historical-docs/)，不要求随源码包分发。

## 1. 角色与通信

| 角色 | 论文p5 §III | 当前实现 |
| --- | --- | --- |
| 客户端S_i | 本地训练、加密上传；每个连接一个边缘 | `clientN`；首次完整提交与证明密封给归属边缘，验证后的密文core随后共享 |
| 边缘A_τ | 分布式建钥、共享验证函数钥、验证所连接客户端、筛选授权、合并 | `authorityN`；归属边缘执行原始证明核验及VerDec，其他边缘认证并共享结果，共同决定授权清单 |
| 云R_t | 接收聚合函数钥、独立部分解密 | `aggregatorN`；达到云门限的合法份额用于合并，云之间不通信 |
| 验证者V | p6抽象DMAFE定义持函数钥的V；p9具体DGFlow由归属边缘执行VerDec | 归属边缘解封函数钥并执行VerDec；主控只转发密封钥，取得允许公开的密文core及签名评分 |
| 控制面 | 论文未指定独立coordinator的网络、授权与泄露模型 | coordinator调度、状态、导出及同源TensorBoard；也是持功能钥的观察方和当前控制面可用性单点 |

客户端没有彼此通信，云也没有彼此通信；边缘之间协作DKG和函数钥/授权。不是把所有节点全连接，也不是三个边缘各自重复核验每个客户端。`client_authorities`唯一映射及轮流分配是项目工程规则，论文没有指定映射算法。

## 2. 当前规模与执行方式

新部署默认n=6、w=3、v=4、ς=2、ϵ=2；n范围2–100，w/v范围2–32，门限2至对应节点数。历史集群按自身声明和节点身份读取，不自动变成默认四云。本次真实攻击小矩阵显式为6/3/3，不能说已经测试6/3/4或论文n20/v4。

来源：[topology.py](../../src/dgfl/topology.py)、[控制API](../../src/dgfl/services/control.py)、[角色](../../src/dgfl/services/roles.py)。API、页面及基准CLI目前允许100全局轮、20本地epoch，已经不再受旧20轮/5epoch上限阻断；入口可设不等于对应规模已完成。

论文p10使用n=20、v=4，未披露w与两个门限的具体数值；参数可配置不能弥补该复现空白。项目成员在任务内固定，尚未实现论文p8描述的新σ个客户端在运行中组成新批次。

## 3. 算法到系统的映射

| 层 | 当前入口 | 与论文的关系 |

| 实验编排 | [experiments/runner.py](../../src/dgfl/experiments/runner.py) | 实际授权名单决定聚合；攻击身份只用于模拟注入及事后统计，不作为筛选答案 |
| 训练合同 | [training/model_adapter.py](../../src/dgfl/training/model_adapter.py)、`paper_models.py` | 线性和完整CNN明文路径有不同可信描述符；绑定模型、参数顺序、dtype和预处理 |

| 部署与监控 | `deployment.py`、`services/control.py`、`web/src/` | 数量/门限部署、逐节点遥测、原生TensorBoard、历史与导出，不来自论文算法定理 |

DKG按任务摊销，首轮建立完整认证转录，后续轮次复用同一key_epoch；`round_id`、模型摘要和策略仍绑定每轮密文与信封。论文p8 §V-A对AuthSetup频率存在解释空间，项目记录摊销假设；不能再写成当前每轮重跑DKG，也不能把阶段名`dkg`出现误读成重新运行全部仪式。

| 878538参数CIFAR CNN | 同上，32×32 RGB原图 | 同上，尚未完成完整模型加密联邦训练 |

论文p10只报告PFLlib和参数量，没有作者确认的层配置或commit。项目两卷积两全连接结构是参数匹配的合理重建，不能称为作者确认的FedAvgCNN源码。明文CNN可显式配置位宽/scale；未选精度保留8/128，12/2048是工程量化诊断，不是论文给定参数。加密协议20,000维上限、1GiB逻辑消息限制和CRS/DKG/DLP/合并预算尚待完整CNN逐项设计验收。

“runner/roles零引用CNN”“仅MNIST”“安全链固定650维”“没有ASR”均已不是当前事实。反过来，“CNN已经接入明文角色”也不代表“完整CNN进入密码链”。实际合同与限制见[模型基础](paper-models.md)和[资源预检](../../src/dgfl/experiments/resources.py)。

旧49文件矩阵结束后，当前另合入LUT/NCHW原图加载及默认关闭的LOCALONLY明文向量档案。加载优化保持归一化逐位相同，只消除大float64中间表示；本地档案支持重算已保存向量的筛选/均值/测试预测，不上传客户端原始模型、不证明诚实SGD，也不扩展正式加密路径。完整说明见[模型对照](model-comparison.md)。新全量实验及临时分段DKG候选各自验收，不能追写旧矩阵源码归属或称为完整CNN安全链完成。

## 5. 信任、输入有效性和可用性

论文p8定理3讨论半诚实权威/云；低于ς的秘密份额泄漏不等于低于ς的任意恶意节点都不能阻断协议。当前DKG需要全部边缘的认证转录/ack，异常会中止。部分云缺席时，足够合法份额可恢复；错误份额被拒绝不等于实现自动隔离/重试或拜占庭活性。

单归属验证依赖归属边缘诚实执行。其他边缘认证owner签名的证明结果/评分，再共同授权；它们不重复客户端原始证明。签名一致性不能替代恶意owner下的输入有效性。项目增加的云配对象证明是特定完整性扩展，不能概括为整体威胁模型已经升级到BFT。

2026-10-12之前，主控能读取经RPC返回的G2验证函数钥。当前正式路径已改为由发行边缘把带签名的份额密封给固定owner，`validation_key`及批量接口都返回不透明信封。主控仍取得每个已提交客户端的完整密文core、范数与余弦，包括随后被拒者，但正常转发不再赋予它完整验证函数钥。owner检查用途、轮次、客户端及发行者，并拒绝公开份额降级。这个变化对齐论文的边缘验证职责，不消除允许公开的统计泄露，也不防御持有所有身份文件的单机管理员；发行者仍知道自己的份额。升级需协调全部节点版本并新建任务。

同一key_epoch中，已发G2函数钥可线性组合，也可在历史密文自己的ctx下计算已发参考span内的投影。轮次/上下文的签名和消息检查不等于函数钥代数撤销；论文p7 VKGen公式本身也不带轮次标签。固定批次的参与矩阵论证不能代替这项功能查询泄露分析，更不能由此推断已恢复完整模型。独立[生产代数小例](../../tmp/attack-defense-audit-20261011/streamed-dkg-draft/production-function-span-tiny-v1/result.json)以真实3边缘/2门限、2客户端、4坐标和两个合法非单位参考完成44项检查、36次VerDec对照，运行前后49个实际源文件一致；它没有角色RPC、证明验证、单位基查询或模型恢复，独立于旧攻击矩阵。[当时的只读审查](../../tmp/attack-defense-audit-20261011/streamed-dkg-draft/production-validation-key-trust-review.md)保留为历史证据；其“尚未密封”结论已由上述正式修复更新。持有授权函数钥的owner仍有相同的代数能力。

Lego数值包与外层Sigma的目标联合关系连接范围、平方和、密文、注册密钥及D开口。numeric-only接口不是完整提交验证；完整v1的负测试未发现已构造绕过，但不能代替知识可靠性证明。修订LegoSNARK的double-binding、Dock接口映射和Fiat–Shamir提取器组合尚未完成正式归约/外部密码审查。额外任务字段绑定也不能自动推出“完整方案更安全”。详见[证明规格](../protocol/proof-construction.md) §15。

固定二人组保留MRPL所需的同批参与列一致前提；没有覆盖任意已知同伴输入、合谋或侧信息。成员无效/缺席会连带同伴，奇数末位不聚合；`regroup`只作可用性对照，不具有同一固定批次结构。论文σ可配置与运行中加入尚未实现。

## 7. 当前结论与历史记录

项目已具备参数化单归属拓扑、真实密码链小模型、数据与攻击指标、固定批次和完整CNN明文合同。缺口包括完整CNN加密链、论文规模攻击比例/多种子扫描、动态批次、生产CRS和组合安全审查，以及四个论文对照基线。可配置和测试通过不能代替这些验收。

10月4–7日的三云、逐位证明、每轮DKG或regroup记录继续代表当时版本；新实验默认为fixed与Lego，历史解析保留旧默认。原始时间和通信数字不改写；论文p11每客户端payload与项目全部RPC字节数不同，当前共机实验也不用于速度比较。引用历史文档时使用带日期的原记录，引用当前行为时使用本文及明确的源码/报告版本。
