# 为什么密码学创新点在当前作品里"看不见"

诊断日期：2026-10-12。基于本检出的**实际运行测量**，不是文档转述。
复现脚本：`tmp/audit-crypto-cost.py`（只读，d=650，3 边缘 / 2 门限，CPU）。

---

## 0. 结论先行

**创新点其实都在代码里、而且都对；问题在于"评价口径"完全没有对准它。**

最刺眼的一组数字（本次实测，d=650，单客户端单轮）：

| 环节 | 实测耗时 | 密码学角色 |
|---|---|---|
| `Encrypt`（650 坐标，48 B/坐标） | **0.120 s** | DMAFE 加密 |
| `VKGen`（3 个边缘的 G2 函数钥份额） | — / **288 B 总计** | 函数钥分发 |
| **`VerDec <x,z>`（授权内积）** | **0.043 s** | **← 论文最核心的新原语** |
| `AggDec`（3 个云各算一次） | **9.2 s** | 云部分解密 |
| `AggComb`（2-of-3 合并） | **14.7 s** | 门限合并 |
| 客户端输入证明（当前部署实际运行的 `lego_norm_v1` 完整提交） | 生成 + 验证 ≈ 秒级 | 144,777 B |
| （对照）legacy 逐坐标 Σ 证明 | prove 13.3 s / verify 12.3 s / 1,915,609 B | 历史套件 |

**论文真正的创新——"不解密就能算出模型与全局模型的内积"——只要 0.043 秒和 288 字节。**

而评审在文档里看到的是一堆 9 秒、15 秒、144 KB、650 维、82.95%、以及"Hmm 标签投毒漏检了"。**新原语被它自己不必要的外壳彻底淹没了。**

## 1. 从源码看，创新点到底是什么

### 1.1 论文宣称的三条创新 vs 代码实际

| 论文宣称 | 代码实际 | 评价 |
|---|---|---|
| **DMAFE**：双解密（VerDec + AggDec），去中心化多授权方，消除 KEP | `protocol.py:279` `validation_key`、`:704` `validate_inner_product`、`:1029` `_aggregate_numerators`、`:1040` `partial_decrypt`、`:1057` `combine` | ✅ **完整实现，代数正确** |
| **鲁棒输入验证**：NIZK 把 L2 范数绑到密文 | `lego.py` + `linkage.py`：`ct=f·s+G·x`、`K=G·s+H·r`、`D=ΣQ_j x_j+Q_v v`，同一个 `zx`/`zs` 共享响应 | ✅ 实现，**但机制是通用的，不是论文独有的** |
| **综合评估**：≥28% 提速、≥83% 省通信 | 未复现论文四个基线 | ⚠️ 未做，且**不能移植论文数字** |

### 1.2 逐层拆解"新颖性"的真实成分

**(a) DMAFE 的加密与 VerDec ＝ 内积函数加密，不是新原语**

```python
# protocol.py:282-283
value = sum(s*int(z) for s,z in zip(self._s[self._row(cid)], reference)) % ORDER
return {'key': b.g2_dump(b.G2*b.scalar(value))}          # VKGen: G2·<s,z>

# protocol.py:711-718
vk      = b.g2_msm([...], weights)                        # 门限插值 Σλ_a·G2<s_a,z>
combined= b.g1_msm(ciphertext, reference)                 # Σ_j ct_j·z_j
value   = b.GT.multi_pairing([combined, -hash_point(ctx)], [b.G2, vk])
#       = e(f,G2)^{<x,z>}
```
这就是 **Boneh–Franklin IBE 型内积函数加密**，与 Chotard et al. ASIACRYPT'18 的 DMCFE 同构。**单独看不是一个新原语。**

**(b) "双解密"在代数上不成立**

- VerDec 计算 `<x, s·z>`（用 **s**）
- AggDec 计算 `<x, y>`，其中 y 是**授权指示向量**，与 s 无关

两者是**同一个内积机制、换了不同的函数向量**。"双解密"是**两次函数求值**，不是两种密码机制。

**(c) "密码学纠缠（cryptographically entangled）"——没有可核实的代数支撑**

论文（p3–4）说 VerDec 与 AggDec 由"同一批相关密钥材料"导出、任何绕过验证的尝试都会在数学上使聚合失效。**在实现里找不到这个约束**：

- AggDec 链：`aggregate_keys(approved,…)` 只用**授权集合的 s 之和**，**完全不引用客户端自己的 `s_j`**。
- 唯一能算作"纠缠"的是 `protocol.py:328` 的同 epoch 检查 —— 那是**运行时守卫，不是代数约束**。
- NIZK 连接的 `K_j = G·s_j + H·r_j` 覆盖了 `(s_j, r_j)`，**但没有覆盖 `y`**。它连接的是密文↔函数钥**分发**，不是函数钥**取值**。

**换句话说：`y` 想怎么选就怎么选，NIZK 不管。** 验证与聚合之间没有"绕过验证就聚合失败"的数学关系。

> ⚠️ 这是最危险的一条。如果评委按论文那句话去追问"绕过验证如何使聚合在数学上失效"，当前实现答不上来。**继续沿用"entangled / 内在绑定"的表述会反噬。**

**(d) 真正扎实、但项目完全没拿出来说的两条**

1. **函数钥的熵分离是严格可证的。** 整个方案的秘密熵只来自 `{s_j}`（每个边缘持有 `s-1` 次多项式的份额）。
   - 由 (a)，`VK` 是 `s` 的**线性泛函** → 少于 s 个边缘时，被查参考向量方向上的信息**恰好就是允许公开的那个内积**，不泄漏别的。
   - 由 (c)，`AggDec` 的 G2 钥是 `G2·h(cloud_id)`，`h` 次数 `e-1`；**少于 e 个云无法插值出 `h(0)`**（这是 Shamir 的信息论下界，不是计算假设）。
   - 而且 `D_j = e(Σct_j, G2)` 是**纯公开可算**的（见下）——安全性**完全落在 `E_j` 上**。
     这意味着"少于 e 个云什么也得不到"是**无条件**的，不依赖 DDH。**这比论文自己的定理陈述还强一点，而文档里一个字都没提。**

2. **验证云部分解密的配对象证明**（`protocol.py:744`，`DGFL-AGGREGATE-PAIRING-V1`）：
   ```
   T^zs = B·E^c ,  G·zs + H·zr = A + c·C(t)
   ```
   云**只知道 G2 像，不知道标量**，却仍必须证明 `E=T^s` 的指数与已承诺的多项式一致。这是**本项目自研的**、论文里没有的机制。

**(e) MRPL 与固定批次是"结构性论证"，不是密码学原语**

`policy.py:143-176` 的固定组保证同批客户端跨轮参与列严格相同 → 选择矩阵秩亏。这是**线性代数论证**。项目为此把默认改成 `fixed`、σ=2，并如实报告了连带排除代价（诚实排除可达 50%）。方向正确，但它不该被列在"密码学创新"里。

### 1.3 实测：函数钥绑定到底是"绑定到一个向量"还是"绑定到一个张成空间"

我实际跑了这个实验（`tmp/audit-crypto-cost.py` 的同系列）：

| 场景 | 结果 |
|---|---|
| 只用为 `z=[1,2,0,-1]` 签发的 VK，去算 `<x, z2=[0,1,1,1]>` | **被拒**：`discrete logarithm outside authorized range` |
| 同上，并显式传入公开的 `norm_squared` 收紧区间 | **仍被拒** |
| 边缘**合法地为 z 和 z2 各签发一次**，然后线性组合两个 VK 得到 `z+z2` 的钥 | **被接受**，返回正确内积 |

**精确结论**：已签发的 VK 是**线性泛函**，签发 N 个参考就隐含授权了它们的整张成空间 span。系统靠 `roles.py:799`（`payload` 必须恰好是 `{client_id}`，参考向量由 authority 自己的 `self.reference` 决定）+ `roles.py:667`（`digest(reference) == ctx['model_hash']`）在**协议层**把它限制成每个 epoch 只有一个参考。

**这是好消息也是坏消息**：
- 好：正常部署下"拒绝随请求换参考向量"是真的（我验证了乱配会被拒，且拒绝来自"配对结果落在授权小窗口之外"这一密码学原因，不是守卫）。
- 坏：**这不是密码学上的向量级绑定，而是协议层的单次使用约束**。面试官若问"函数钥能否复用/组合"，当前文档（`paper-gap-analysis.md:41`、`architecture-comparison.md:60`）其实已经承认了 span 问题——**但正文仍在说"绑定本轮参考模型"**，两处口径需要统一。

## 2. 为什么"看不见"：四个根因

### 根因 1：没有基线，测量口径全部指向外壳

现有实验模式是 `plain / encrypted / dgflow / optimized`。这四个**全都带着同一套外壳**（Lego 证明 + 650 维 + 完整 DKG + 门限聚合）。所以：

- `encrypted` vs `dgflow` 的差异 = 一个相似度筛选器；
- `optimized` vs `dgflow` 在代码里**同分支**，差异只在调度；
- 于是"用了什么密码学"在数据上完全不可区分。

**评审拿不到任何可以回答"我这个新原语值多少"的数字。**

### 根因 2：新原语的开销被解码和外壳淹没

| 成本来源 | 量级 |
|---|---|
| **内积机制本身** | **0.043 s**（1 次 MSM + 1 次 multi-pairing） |
| 有界离散对数解码 | VerDec 时小（内积是标量）；**聚合时每坐标一次 → AggComb 14.7 s** |
| 650 坐标的逐坐标 Σ 线性 | 与"范数绑定"这个目标**无关**的线性开销 |
| Lego 数值电路 | 6501 条约束，为"范围"而引入 |

**最核心的那一行只花 0.043 秒，却被放在一个 9–15 秒的轮次里报告。**

### 根因 3：架构新颖性（密钥怎么发）在输出里完全不可见

真正对得起"去中心化多授权方"这个名号的东西：

- `Authority` 的**双多项式 Pedersen DKG**（`protocol.py:113-263`），每个边缘对每个客户端**每一坐标**生成独立的 `S_aj(X)`、`R_aj(X)`；份额逐项对承诺验证；equiocation 检测；`finalize` 清除 dealer 多项式。
- **函数钥信封**：`roles.py:798-815` 只接受 `{client_id}`，份额密封给固定 owner，`owned-validation-key` 机制（2026-10-12 修复，把主控从"可读函数钥"降级为"纯转发"）。
- **单归属拓扑**：`topology.py:36-46`，客户端只连一个边缘。

这些在**任何一条输出曲线里都不会出现**。它们只在源码和文档表格里，而文档用了"分层职责/唯一归属"这种工程语言来叙述，恰好把密码学含量最高的部分讲成了架构描述。

### 根因 4：负面结果（投毒漏检）在叙事上盖过了正面结果（范数绑定）

报告里最显眼的是：CNN 30% 定向投毒 10 轮全部通过筛选（OA 65.12% / ASR 33.96%）、CIFAR 漏检、seed43 第二轮漏检。

这些是**诚实且必要**的。但论文的密码学主张其实是：

> **"提交的 `Xi` 保证由密文里的 `{x_j}` 算出"** —— 即 **ESFL 的伪造范数绕过在数学上不可能**。

而项目**做到了**这件事（`tamper_proof` 攻击：证明无效被拒；`tests/crypto/test_screening_information.py` 还用真实 Lego+DKG 证明了两组不同合法向量可以有相同平方范数与相同内积——这是**数学特征不足的严格回归**，非常漂亮）。

**问题**：文档把"我们挡住了伪造范数"和"我们挡不住标签投毒"写成了同等权重的段落，读者只记住了后者。

## 3. 修复方案

### A. 立刻可做：一个"原语性能台账"实验（半天，零新密码代码）

新增一个实验模式或独立脚本，**固定其它一切、只切换密码组件**，输出一张评审一眼能读懂的表：

| 配置 | 密文大小 | 证明大小 | VerDec | 聚合 | 说明 |
|---|---|---|---|---|---|
| P0 明文 | — | — | — | — | 基线 |
| P1 纯 DMAFE（**不生成输入证明**） | 31,200 B | 0 | **0.043 s** | 9.2 s | **新原语的真实成本** |
| P2 DMAFE + legacy 逐坐标 Σ | 31,200 B | 1,915,609 B | +1 次全量验证 | — | 历史套件 |
| P3 DMAFE + lego_norm_v1（当前默认） | 31,200 B | 144,777 B | 秒级 | — | 当前部署 |
| P4 P1 + 伪造 Xi | 31,200 B | 0 | 内积错配 → 拒绝 | — | 说明**为什么必须有证明** |

这张表直接回答"你的创新值多少、代价是什么、为什么值得"。

**关键点**：P1 那一行必须在表里。它是唯一能让"0.043 秒 / 288 字节"这个数字出现在评审眼前的载体。

### B. 重新表述创新点（最高优先级，纯文档工作）

**删掉**这些站不住的表述：
- ❌「双解密在密码学上纠缠（cryptographically entangled）」
- ❌「任何绕过验证的尝试都会在数学上使聚合失效」
- ❌「DMAFE 是一个新原语」（应当说"内积函数加密在去中心化多授权方设置下的实例化 + 认证门限解密"）

**改成**这三条可核实的命题：

1. **函数钥在熵上分离**：方案的秘密熵只来自 `{s_j}`；`VK` 是 `s` 的线性泛函，故被查参考方向上释放的信息**恰好等于**该内积；少于 s 个边缘无法恢复 `s`。（这是**可证的**，且在代码里可指到 `protocol.py:279-283`。)

2. **门限聚合是无条件安全的**：`D_j = e(Σct_j, G2)` **纯公开可算**（我实测确认），安全性完全落在 `E_j = Π_t E_{j,t}^{λ_t}`；少于 e 个云无法插值 `h(0)`（Shamir 信息论下界）。**比论文的 honest-but-curious 定理更强**——因为 `D` 根本不藏东西。

3. **验证与聚合的能力是分开签发的**：`VK`（G2 标量、单参考、密封给固定归属边缘）与聚合钥（G2 多项式份额、密封给指定云、附配对像证明）由**不同算法、不同门限、不同接收方**产生。这是**系统级**的访问控制贡献，而不是代数贡献——**如实这么讲反而更有说服力**。

把"span 问题"从文档角落提到正文的"边界"一节，用我实测的两行结果说明：**正常部署因单参考约束而受限，但这是协议约束不是代数约束。**

### C. 补一个真正的密码学增量（如果还有时间）

**目前最大的浪费**：为了证"范数 = 坐标平方和"，用了一个通用的 Groth16 电路（6501 约束）——**而这个关系可以在群运算里几乎免费地断言**：

```
∏_j ct_j^(x_j) 的盲化版本 与  Xi 承诺的关系
```

也就是说，`x_j` 在 `ct_j = f^{s_j}·g^{x_j}` 里**本来就以 G1 指数形式存在**，`s_j` 的掩码可以像 VerDec 那样用配对消掉。用通用 SNARK 来证一个"本可配对验证"的关系，是把项目的**性能卖点主动丢掉**。

已经有了 `K_j = G·s_j + H·r_j` 这个带**每坐标独立盲化**的 Pedersen 结构，最有价值的增量是：

> 设计一个**专用的 Σ-协议 / 同态论证**，同时绑定 `{x_j}`、`Xi = Σx_j²` 与 `{ct_j}`，只用群运算，不用通用 SNARK。
> 预期：证明从 144,777 B 降到 ~KB 量级（≈ 几十个群元素），证明时间从秒级降到毫秒级。

这将是**项目自己的**密码学贡献，而且直接对上论文"efficient"的主线叙事。**但必须标注为"未获外部审计的实验性构造"**——项目在这方面的边界声明一直做得很好，继续保持。

### D. 改变演示顺序（现场 5 分钟就能救回来）

不要从"6 客户端 / 650 维 / 82.95%"开始。改成：

1. **先给那张台账表**（A 的成果）：一句话——"核心机制 0.043 秒"。
2. **再演示熵分离**：现场用 2 个边缘（< s=2 门限？不行）→ 改用 3 边缘 2 门限，**实际只给 1 个份额**，展示 `recover_client_key` 报错、且拿到的东西不含任何 `x_j` 信息。
3. **演示门限**：给 1 个云的结果 → `combine` 报 `cloud threshold not met`；给 2 个 → 正确恢复。**并指出 `D` 是公开可算的，所以这个门限是无条件安全的。**
4. **演示函数钥绑定**：`roles.py:799` 请求任意第二个参考向量 → 被拒。**并主动说明 span 边界**（诚实反而加分）。
5. **最后演示范数绑定**：同一模型、`Xi` 改成 `Xi+1` → 证明无效被拒。这是**ESFL 会放过的攻击**。
6. **最后才提投毒漏检**，并明确："我们保证的是范数声明的真实性，不是投毒检测的完备性——这是两个不同的密码学主张。"

---

## 4. 一句话总结

> **创新点不是"看不见"，是被项目自己用错误的度量方式、过度膨胀的宣称、和一份太诚实的负面结果清单挡在了后面。**
>
> 真正值钱的那一行只花 **0.043 秒、288 字节**，而它现在被埋在 9–15 秒的聚合耗时和 144 KB 的通用 SNARK 证明里；论文那句"密码学纠缠"在代码里没有代数支撑，继续宣传会反噬；而**两条真正可证、且比论文更强的性质（函数钥熵分离、门限聚合的无条件安全性）文档里一个字都没提**。
