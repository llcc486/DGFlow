# 模型实现与指导论文的当前对照

更新：2026-10-11。依据[指导论文](../DGFlow-指导论文.pdf)第10页及当前源码。项目已有两条不同路径：小型池化线性模型运行真实密码链，参数量匹配的完整CNN运行明文训练与聚合。两者不能互相替代为论文CNN的安全联邦学习结果。

本次重写前的全文及SHA-256保存在[历史文档快照](../../tmp/attack-defense-audit-20261011/paper/historical-docs/)。旧文中的“仅MNIST”“CNN未被runner/roles使用”“最多5个本地epoch”“全部证明仍是逐位材料”等结论已经过期；旧测试和计时仍只代表其原始版本。

## 1. 论文已披露什么

论文p10 §VI使用PFLlib，在20个客户端、4个云服务器上评估MNIST和CIFAR-10；CNN参数数目分别为582,026和878,538。MNIST性能实验为10个全局轮次、每轮10个本地epoch，CIFAR-10性能实验为30个全局轮次。论文p12攻击随轮图延伸至100轮，不把不同图的设置合并成同一个实验。

论文没有给出完整逐层配置、作者使用的框架commit、学习率、mini-batch大小、量化位宽/scale、边缘节点数及两个门限的具体取值。项目参考PFLlib结构重建参数量匹配的两卷积两全连接模型；参数数量一致是可核对的事实，不证明作者实际采用同一实现。CIFAR-10的本地epoch也不因MNIST写了10而自动补成10。

## 2. 当前四种模型路径

| 模型 | 输入及参数数目 | 当前训练路径 | 密码链范围 |
| --- | --- | --- | --- |
| MNIST线性 | 28×28灰度图，经默认8×8池化；64个特征，650参数 | NumPy或Torch CPU，float64线性softmax | 已运行真实Lego、DKG、VerDec、授权、门限部分解密及合并 |
| CIFAR-10线性 | 32×32 RGB图，经默认8×8逐通道池化；192个特征，1,930参数 | 同上，保留RGB通道 | 同上；真实数据已接通，不是合成图片占位 |
| `paper_cnn_mnist` | 原图N×1×28×28；582,026参数 | Torch，float32，所有层训练；接入页面/API/runner/客户端明文路径与逐epoch监控 | 必须显式`mode=plain`；encrypted/dgflow/optimized在CRS、DKG和任务绑定前拒绝 |
| `paper_cnn_cifar10` | 原图N×3×32×32；878,538参数 | 同上 | 同上，尚未完成完整CNN加密联邦训练 |

线性模型维度为`10 × (channels × grid² + 1)`。当前公开入口MNIST网格2–28，最高7,850参数；CIFAR-10在20,000维限制下为2–25，最高18,760参数。CIFAR网格26会得到20,290参数并被拒绝。通用图像辅助函数允许的网格范围不等于完整实验入口允许的密码维度。

API、页面及基准CLI允许最多100个全局轮次、20个本地epoch；可配置不等于所有组合已经完成验收。训练设备与密码计算设备分别配置；线性Torch路径仍使用CPU float64，不能由选择密码GPU推出模型训练也在GPU运行。CNN训练工厂支持显式CPU/CUDA设备，当前CPU测试不能替代实际CUDA验收，不会无提示回退CPU。

## 3. 完整CNN结构与参数布局

两套重建网络均为`Conv5×5 → ReLU → MaxPool2×2 → Conv5×5 → ReLU → MaxPool2×2 → Flatten → FC512 → ReLU → FC10`。卷积步长1、无填充；卷积与全连接都含偏置。ReLU和池化没有可训练参数，全部卷积/全连接参与SGD。

| 层 | MNIST输出（不含batch） | MNIST参数 | CIFAR-10输出（不含batch） | CIFAR-10参数 |
| --- | --- | ---: | --- | ---: |
| 输入 | 1×28×28 | 0 | 3×32×32 | 0 |
| Conv1 + ReLU | 32×24×24 | 800 + 32 | 32×28×28 | 2,400 + 32 |
| MaxPool1 | 32×12×12 | 0 | 32×14×14 | 0 |
| Conv2 + ReLU | 64×8×8 | 51,200 + 64 | 64×10×10 | 51,200 + 64 |
| MaxPool2 / Flatten | 64×4×4 / 1,024 | 0 | 64×5×5 / 1,600 | 0 |
| FC1 + ReLU | 512 | 524,288 + 512 | 512 | 819,200 + 512 |
| FC2 | 10 logits | 5,120 + 10 | 10 logits | 5,120 + 10 |
| **合计** | — | **582,026** | — | **878,538** |

CIFAR比MNIST多296,512参数，其中294,912来自第一全连接层更大的展平输入，1,600来自第一卷积层的额外两个输入通道。参数多不意味着墙钟耗时按相同比例增加；卷积运算、样本数、batch、数据复制、后端以及密码链的不同阶段都影响总耗时。

完整CNN按`named_parameters()`顺序导出，每张量按C序展平，dtype固定float32。布局如下，区间为左闭右开：

| 参数 | MNIST形状 / 向量区间 | CIFAR-10形状 / 向量区间 |
| --- | --- | --- |
| conv1.weight | [32,1,5,5] / [0,800) | [32,3,5,5] / [0,2400) |
| conv1.bias | [32] / [800,832) | [32] / [2400,2432) |
| conv2.weight | [64,32,5,5] / [832,52032) | 同形状 / [2432,53632) |
| conv2.bias | [64] / [52032,52096) | [64] / [53632,53696) |
| fc1.weight | [512,1024] / [52096,576384) | [512,1600] / [53696,872896) |
| fc1.bias | [512] / [576384,576896) | [512] / [872896,873408) |
| fc2.weight | [10,512] / [576896,582016) | 同形状 / [873408,878528) |
| fc2.bias | [10] / [582016,582026) | [10] / [878528,878538) |

可信清单记录结构、输入形状、层选项、参数名称/顺序/形状/dtype及架构摘要；摘要不包含权重、种子、设备或train/eval状态。[模型合同](../../src/dgfl/training/model_contracts.py)和实际工厂必须一致。装载前检查摘要、维度、dtype和有限性，不能让调用方只提交相同维度便替换模型语义。这种绑定用于防止接口混用，不证明远端真的进行了诚实SGD。

## 4. 数据、训练和监控语义

MNIST和CIFAR-10均有真实下载准备、校验及离线加载路径；原始完整训练/测试集分别为60,000/10,000和50,000/10,000。是否使用全量取决于实验中记录的`train_limit/test_limit`，不能把1200或6000样本子集称为全数据。公开配置和基准检查所选数据集的上限；原图底层loader自身按可用split截取前缀，基准再检查实际返回数量是否与请求一致，不静默将CIFAR的60,000请求冒充完整60,000。

线性模型采用floor/ceil分箱的自适应平均池化、除以255后按CHW C序展平。非整除网格的池化窗口可能重叠，不应写成每个原像素恰好使用一次。CNN保留原分辨率与通道，不做该池化，不隐式增加数据增强或均值/方差标准化。

本轮合入[原图加载器](../../src/dgfl/training/original_images.py)后，CNN直接建立所保留前缀的连续NCHW float32数组。只含256项的只读LUT逐像素重现`uint8 → float64除以255 → 转float32`的**相同位模式**，以最多32张的索引缓冲归一化，避免整份图像先实体化成float64。可信预处理描述符保持原有语义；这不是改变训练归一化。MNIST流式读取IDX，CIFAR按记录块读取；即使只保留前缀，也读完文件并核对大小、标签和尾部损坏。该函数不下载、不导入Torch；发布来源哈希仍由显式数据准备或离线基准核对。

仅计算图像输出数组，完整MNIST两split的float32载荷约209.35MiB，CIFAR-10约703.13MiB；这不含标签、压缩/解码缓冲、分区副本、模型/梯度、Torch运行时和密码材料。LUT消除大float64中间表示，不给整个训练进程或多节点部署设定内存硬上限。内存和速度仍须按实际并发与样本数测量。逐位等价、独立解释器不导入Torch及保留前缀之外损坏仍拒绝等边界见[加载测试](../../tests/training/test_original_images.py)。

CNN的`train_local`用普通SGD与交叉熵；适配器默认学习率0.01、batch64。没有隐式动量、权重衰减或调度器，训练返回完整本地模型而非更新差分。批次由固定seed的NumPy生成器排列，CPU保存样本，仅当前batch送往训练设备。这些具体超参数是工程重建假设，不是论文披露值。线性路径保留原有学习率与更新语义。

每个本地epoch记录该客户端实际训练分区上的准确率/交叉熵，累计epoch为横轴；它发生在量化及训练后攻击变换之前。标签投毒时“实际训练标签”可能已经被改动，不能当作真实标签测试精度。新增评估/回调时间单列，不重复SGD、不改变最终权重；全局指标使用独立测试集真实标签。一个客户端在其偏斜训练分区上得高分，不意味着其模型在完整测试集也得高分；参数平均也不是准确率平均。相关测试见[训练监控](../../tests/training/test_cnn_monitoring.py)和[真实明文角色合同](../../tests/integration/test_cnn_plain_model_contract.py)。

## 5. 量化与完整CNN当前效果

`paper_models.train_local`本身只做浮点训练；角色明文路径仍在上传/聚合边界应用量化。当前量化对每个坐标先限幅，再乘scale并四舍六入、正好一半取偶数，整数范围为`[-2^(bits−1), 2^(bits−1)−1]`；下一轮从整数全局模型除以scale恢复。`plain`因此不等同于不量化的浮点FedAvg。

省略精度时维持历史8bit/scale128。CNN可显式选择2–16bit、scale1–65,536，页面12bit/2048预设是诊断配置，不是论文给定参数或准确率保证。提高scale同时影响步长、可表示实数区间及内积整数预算，不能只看其中一项。

已结束的MNIST明文组件记录采用原图、582,026参数、20客户端、训练/测试6000/1000、seed42、10轮×10本地epoch、学习率0.01和batch64：

| 已结束组件实验 | 第10轮测试OA | 解释范围 |
| --- | ---: | --- |
| 每轮8bit/128量化聚合 | 15.1% | 筛选/不筛选模型逐轮一致，全部接纳；未发生坐标裁剪 |
| 每轮12bit/2048量化聚合 | 84.3% | 初始量化也不同，不能当作仅改后续聚合的单因素对照 |
| 从重建的同一8bit初始模型开始，之后浮点FedAvg | 85.1% | 原记录未存初始模型哈希，明确区分确定性重建与直接历史哈希 |
| 12bit/2048，无攻击复跑 | 两模式均84.3% | 10个逐轮模型哈希一致；旧记录无完整向量，未独立重算预测 |
| 12bit/2048，30%跨组定向标签翻转 | 两模式均40.0% | 六恶意每轮全被接纳；ASR582/1000，条件ASR582/893，不能宣称筛选抵消了攻击 |

完整配置、版本、分母及证据边界见[攻击防御核验](attack-defense.md#完整cnn量化诊断)。上述都是明文组件，不是完整CNN的Lego/加密角色实验，也不是全部60,000/10,000样本。当前全量向量存档实验另行运行；在它终态并完成回读前，不报告其最终准确率或完成结论。

旧49文件冻结版本的14项真实加密小模型实验已结束，包含MNIST种子42/43、跨pair攻击及两数据集Non-IID clean。它们早于本轮LUT/NCHW和本地向量档案合入，不能升级成当前新源码的指纹验收，也不与更早47文件矩阵混成同版本多种子统计。保留的seed43、split与CIFAR漏检详见[论文差距分析](paper-gap-analysis.md#3-已完成实验与实际失败)及[14项最终汇总](../../tmp/attack-defense-audit-20261011/benchmark/followup14-final-v1/summary.md)。

## 6. 默认关闭的本地完整向量档案

[明文组件工具](../../scripts/benchmark_paper_defense.py)新增显式`--save-local-diagnostic-vectors`，默认关闭。启用后只在所选新实验目录保存本地明文int64初始参考、每轮输入、全部客户端向量及聚合向量；这是有权限的隔离诊断，不将原始本地模型上传到主控/云，不接入正式角色RPC，不改变训练、筛选或聚合。正式结果导出也不能因这项诊断而自动包含原始客户端模型。

档案预检容量估计为`(1 + modes × rounds × (clients + 2)) × (dimension × 8 + 4096)`，超过显式磁盘预算或可用空间会在训练前拒绝。默认预算2GiB；MNIST20人、10轮、两mode共441个文件，向量载荷约1,958MiB，额外记录还需空间。它是磁盘存档预算，不是运行RAM上限。写入拒绝覆盖、限制路径在本地输出目录内，并记录规范小端向量摘要和NPY文件摘要；保存开销单列。失败与不完整轮次保留，缺失结果不补零。

[独立回读工具](../../scripts/readback_paper_defense.py)要求同源码记录与显式档案，验证实际来源文件、原始数据、全部分区、可信模型合同、向量哈希和轮次继承，再从完整向量重算范数/余弦、固定批次、整数均值和已完成轮次的独立测试预测/OA/ASR；失败轮可核对已有材料，仍保留失败状态。它不重新训练SGD，也不证明向量由诚实训练产生；没有档案的旧记录不能被伪装成已独立重评。该机制及开关权重一致测试见[档案实现](../../scripts/paper_diagnostic_vectors.py)、[真实CNN档案测试](../../tests/experiments/test_paper_diagnostic_vectors.py)。

## 7. 完整加密CNN仍需完成什么

当前大模型明文入口明确绕过加密20,000维上限，但没有把大模型放进现有密码协议。现有自动分块只拆分HTTP请求，单次逻辑消息仍限制1GiB；资源预检用编码下界拒绝确定超限配置，通过下界检查并不保证实际消息/RAM足够。详见[资源预检](../../src/dgfl/experiments/resources.py)。

Lego的数值SNARK可以很小，但完整提交仍含按坐标增长的外层关联材料，不能把整体证明/通信称为恒定大小，也不能沿用旧逐位透明证明估算当作当前Lego实测。CRS/证明密钥、DKG转录、每客户端密文、函数钥、云部分解密与确认材料分别需要预算；真实内积恢复还取决于经验证范数给出的DLP区间和所选算法，不只取决于参数数目。Cauchy–Schwarz区间收紧已经接入小模型路径，不再列为未实现建议。

临时分段DKG候选已另行做20,003维组件探测，但未合入正式角色私有传输，也未运行完整CNN密文链；单独组件可行不能替代全部材料的内存、消息、隐私和安全组合验收。当前单方开发CRS与Lego外层double-binding组合的正式安全归约/外部审查也仍是独立缺口。

因此后续应逐项验收完整CNN加密路径及生产设置，再对齐论文规模、攻击比例、多种子、Non-IID与四个论文基线。小样本单客户端秒数、明文CNN耗时或共机矩阵时延均不能直接外推为论文级10轮安全训练时间，也不能由调高维度上限宣称完成复现。协议/拓扑的其他当前差异见[架构对比](architecture-comparison.md)。
