## 2. 立即实施的独立交付

### 2.1 保持密码协议不变的计算优化

- 校对 `py-arkworks-bls12381==0.5.0` 的受检解码实现；在底层已检查曲线与子群的前提下去掉重复子群检查，保留规范字节长度、回编码及恶意点拒绝测试。
- 为长的 G1/G2 线性组合使用原生 MSM；在调用前校验两输入等长，所有网络点仍经过受检解码。
- 将公开上下文、Lagrange 系数和固定解码边界的重复计算移出坐标循环或使用有界缓存。
- 保持密文、证明转录、随机源、每轮 DKG、门限、授权集合和量化区间不变。
- 保留每条证明关系的确定性验证；不在这一步引入概率批量验真。
- 使用真实 DKG/证明/内积/门限聚合的微基准与负测试，保留源文件摘要、维度、客户端数、缓存口径。微基准不得标成全系统训练提速。

### 2.2 论文规模 CNN 训练基础

独立提供 `paper_cnn_mnist` 和 `paper_cnn_cifar10`，匹配 PFLlib FedAvgCNN 的两层卷积与两层全连接结构及论文参数量。记录规范模型清单、参数名/形状/顺序/dtype、架构摘要，严格拒绝不匹配和非有限向量。CPU 与 CUDA 显式选择，不可用的 CUDA 不得静默回落。

这是有依据的架构重建，不是获得了作者源码。独立本地训练通过不等于当前服务支持这些完整向量加密。本次不将未完成的安全大模型路径放入界面，以免错误宣告可用。

## 3. 大模型接入的必要设计

### 3.1 传输与内存

当前限制：密码维度最多 20,000；训练服务曾固定 650；单次 RPC 上限 64 MiB；大对象曾以十六进制 JSON 重复存储/传输。现有 8 位证明每坐标约 2,576 字节原始点/标量数据；582,026 坐标约 1.396 GiB；未计密文与认证封装。这是字段长度推算，不是新实测通信量。

> **更新（线格式修订后）**：本节列出的三项传输限制已解除——曲线点与标量改为原始字节、载荷改为紧凑二进制、超过 24 MiB 的请求自动分块。实测单客户端封装由 11,450 降到 2,998 B/坐标，同配置单轮 `bytes_sent` 由 304,749,105 降到 70,027,182。模型维度也已参数化（`grid` 2–28，650–7,850 维）。但**证明本身的 O(d·b) 结构未变**：582,026 维仍需紧凑证明才具备可用性，本节其余结论依然成立。详见 [protocol-v1.md](../protocol/protocol-v1.md) 的修订记录。

后续采用规范二进制、受认证分块与有界队列。每块必须绑定任务、轮次、模型清单摘要、密钥周期、客户端、总维度、坐标范围、块编号/总数及整体提交摘要。重放、重叠、缺块、截断、改序或同轮改写必须拒绝；只有整体提交完整且证明通过后才发放聚合许可。

分块只改变计算和存储方式，不额外发布每块范数/内积；论文公开的是整体范数与获授权整体内积。证明的全局挑战和平方和关系必须绑定完整向量，不能把若干独立小模型的成功拼成大模型验证成功。

### 3.2 紧凑证明

现有证明虽可作为流式基线，体积不适合直接宣称论文性能。紧凑替代方案须写清密文、已登记 DKG 密钥、整数范围、整体平方和之间的同一见证绑定，及无模回绕条件。单独换一个范围证明库不自动完成这四种关系。论文省略的转录、量化与范数上限参数要列为复现假设，向作者获取配置后再核对。

### 3.3 边缘验证与拓扑

不能把当前 2/3 独立许可直接换成单节点“通过”签名。在保持当前被攻破节点假设的方案中，需确定每个输入获得足够独立验证，以及全局许可对密文、验证结果和筛选集合的承诺。如果选择论文的诚实但好奇边缘模型以减少重复，必须作为单独配置明确披露其假设，不能称为同安全条件提速。

### 3.4 解码与训练保真

论文规模需重新测算内积的整数边界与 BSGS 内存。不能直接提高现有 100,000 婴儿步上限而忽略资源。保留未量化明文、相同量化明文、完整加密三条路径；记录量化饱和率、误差、最终模型、批准集合，分离训练、量化、筛选和密码的影响。

可进一步研究利用已通过证明的整体平方范数收紧解码区间。设 `Xi=sum(x_j^2)`、`T=sum(z_j^2)`、坐标绝对值上界为 `o`，Cauchy–Schwarz 不等式给出合法整数内积上界 `min(o*sum(abs(z_j)), isqrt(Xi*T))`。应使用精确整数平方根，且必须先验证 Xi 与密文绑定；未经证明的自报范数不能决定成功接受的解码结果。该候选优化尚未接入本次代码或计时，不预先承诺收益。

## 4. 验收顺序

1. 当前小向量密码语义和全部攻击负测试保持通过；证明微基准结果与旧实现一致。
2. 完整 CNN 参数量、展平往返、真实反向传播覆盖卷积层、输入拒绝和设备行为通过测试。
3. 分块协议在小向量上与非分块版本逐整数对齐，并通过缺块/错序/混轮/混模型负测试。
4. 以 650、7,850、分级更大向量验证内存、时间、证明体积和通信，再启动完整 CNN 的真实加密运行。
5. 20 客户端、4 云进程配置完成后开展论文规模研究；长实验保存恢复点与失败记录。

任何尚未运行的规模、准确率和提速都不填成实验结论。当前论文的冷启动聚类、极端非 IID 和回传旧模型攻击仍是开放问题（第 12 页），不能以更换 CNN 自动解决。
