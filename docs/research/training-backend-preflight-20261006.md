# Torch 依赖与空提交错误修复（2026-10-06）

实验 `1486c0d8462949699463b482a9cae9f5` 在 25.162 秒后中止，没有完成训练轮次。配置为六客户端、Torch 训练、Lego 证明和 GPU 密码计算。六名客户端训练均因未安装可选 PyTorch 依赖而失败；主控随后把空 `client_ids` 发送到 `authority1/validation_keys`，节点正确拒绝空批量，但页面只显示最后的 `invalid validation key batch`，掩盖了实际原因。

修复包括客户端 health 和控制状态的轻量依赖检测，使用模块 spec 查询，轮询不会导入 Torch。Torch 可用性按实际训练客户端判断，局域网主控不需要安装 Torch。此检测确认模块存在，不替代训练时的动态库加载检查；加载失败返回受控的依赖错误。

网页禁止选择未就绪的训练后端，已选择的后端若变得不可用则保留选择并拒绝提交。运行管理器在创建记录前重新检查客户端，并在执行阶段、准备数据和建钥前再次核对。不会自动把 Torch 改成 NumPy。现有 NumPy 任务无需额外依赖探测。

训练过程中保存每个失败客户端的安全错误分类；所有客户端失败、只剩一份提交或固定二人组不完整时，在验证之前中止。至少两份合格提交仍可按策略继续，声明成员名单保持完整。没有取消验证密钥的空批量拒绝，也没有减少密码检查。

验证包含 35 个训练失败处理回归、24 个后端检测及启动前检查案例、56 个前端测试，构建和 Ruff 均通过。其他相关实验、集成和传输回归通过；主服务实际验证 Torch 请求返回明确 409，前后实验记录均为 54 条，没有创建新任务。
