# 攻击防御架构验收与竞赛演示

更新：2026-10-12。目标是可解释、可复验的论文架构实现；比赛规模采用小模型，不宣称复现论文全部CNN规模或保证获奖。

## 对齐的实现

| 论文职责 | 当前实现及检查 |
| --- | --- |
| 分层与归属 | n/w/v及两层门限可配置；每个客户端只向一个归属边缘密封提交。没有客户端互联或云节点互联的协议。主控转发边缘协作消息。 |
| 分布式建钥 | 各边缘独立产生秘密与盲化多项式，确认相同DKG转录；主控不先生成完整主密钥。首次建钥需全员参加，任务内复用密钥周期。 |
| 边缘验证权限 | 原始证明和函数钥份额均密封给固定owner。主控只转发，owner核验发行身份、门限、用途、客户端与轮次；不允许公开签名份额降级。 |
| 输入有效性 | 实际LegoGroth16及关联证明绑定密文、编码、密钥、范数和上下文。篡改声明被拒；有效证明不等同于诚实训练。 |
| 异常筛选 | 使用已验证范数和授权内积，攻击者名单只用于注入/事后统计；不交给筛选器。聚类门限是明确记录的工程重建假设。 |
| 不可变批次 | 默认 σ=2；新实验可选择能整除客户端数的 σ，启动后固定并按整组接纳；直接拒绝和诚实同组成员连带分别统计。regroup是显式扩展，不宣称保留固定批次的跨轮隐私结构。 |
| 门限聚合 | 云只接收批准的密文与聚合钥，达到e/v后恢复整数和；主控及边缘核对云结果证明及下一轮模型摘要。 |
| 失败处理 | 错误签名、跨轮消息、重复份额、策略变更和不足门限不发布新模型；中断保存证据，不补造轮次、准确率或检测成功率。 |

正式改动包含：攻击参数与身份校验、真实ASR分子分母、批次连带统计、筛选跨进程确定性，以及公共有界离散对数表缓存。缓存只保存公共固定基底表，仍按原始整数上下界检查结果；局部解码速度改善不能写成整轮训练的等比例提速。

## 可重复的真实节点验收

先按[部署说明](deployment.md)安装依赖，准备MNIST/CIFAR-10缓存和650/1930维、8bit的Lego CRS。以下命令不会下载数据、生成CRS或修改默认运行目录：

```powershell
.venv\Scripts\python.exe -B scripts\verify_attack_architecture.py --runtime runtime-architecture-check --port-offset 31000 --case-timeout 1800
```

必须选尚不存在的运行目录。工具启动6客户端、3边缘、4云的独立进程，使用真实mTLS/RPC和当前正式密码代码；测试结束仅清理自己的节点，保留结果。机器需要空闲的40101–40103、40201–40204、40301–40306端口。它不启动另一份网页服务，也不占用8765。

上述命令给每个案例30分钟预算，适合CPU环境；达到预算会请求停止并保存失败，不把超时记成算法拒绝攻击。现场短演示可加 `--datasets mnist`，完整验收保留两种数据集。

每种数据集依次执行四项：

1. 正常明文基线：2全局轮×2本地epoch。
2. 正常DGFlow：相同数据、分区、种子、量化和轮次，检查全部客户端证明有效且逐轮模型与明文一致。
3. 符号翻转：client1/client2同组，1轮，检查证明有效但统计筛选拒绝。
4. 范数声明篡改：同组攻击，1轮，检查证明无效而被拒绝。

安全案例配置排除2个云，只剩2/4门限参与聚合。这是逻辑排除，不是进程崩溃恢复实验。共同设置为seed42、IID、1200训练/400测试样本、固定批次、NumPy、CPU密码计算；MNIST650维，CIFAR-10为1930维。

主报告为运行目录下的 `architecture-acceptance.json`，包含每项配置、结果、分区哈希、校验结果、源文件前后SHA256及清理记录。原始逐轮结果在 `results/<run_id>/result.json`。只有 `passed=true`、`source_unchanged=true` 且各项已完成才算该次验收成功；失败和超时同样保存。报告中的耗时是此机器的样本，不是论文性能复现。

回归入口：

```powershell
.venv\Scripts\python.exe -B -m pytest tests/integration tests/transport tests/validation tests/crypto/test_discrete_log_cache.py -q
cd web
node --test
npm run build
```

## 答辩时应展示的区别

先展示正常任务与明文结果一致，再对照“证明无效”与“证明有效但被筛选”的两种攻击。验证页分别展示OA、定向ASR、恶意接纳比例、诚实排除和批次连带，不把缺席当作检测成功。TensorBoard本地曲线使用该客户端实际训练标签，不能直接等同于全局独立测试集准确率。

标签投毒的局限必须保留：已完成的20客户端全量MNIST明文CNN组件对照中，30%定向投毒连续10轮全部通过当前筛选，最终OA65.12%、ASR33.96%，筛选与不筛选模型一致；同设置无攻击OA97.88%。它证明当前余弦/范数启发式不能识别所有合法模型投毒，不是密码证明被绕过。更详细配置及原始证据见[攻击防御核验](../research/attack-defense.md)。不为提高演示通过率而按已知攻击者身份删除模型。

可信边界仍包括诚实/半诚实归属边缘、受信初始任务配置和开发CRS。其他边缘认证owner结论但不重复核验原始证明；一致签名不等于完整BFT。单机管理员能访问全部角色私钥，消息密封不能替代物理机构隔离。保留已授权函数输出泄露，不能宣传“完全不泄露”。

完整CNN加密、动态新增批次、任意自适应投毒/后门防御、生产多方设置和正式组合安全归约是后续研究。可演示的小模型协议闭环与明确边界是当前交付重点。
