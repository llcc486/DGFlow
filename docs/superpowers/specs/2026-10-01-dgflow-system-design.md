# 本科密码竞赛作品工程设计约定

作品题目：《基于去中心化函数加密的隐私保护鲁棒联邦学习系统》

状态：基于用户需求与 DGFlow 论文制定的实施设计；尚无产品代码和实测结果。协议细节审查属于首项工作，本文不声称已经解决论文的实现留白。

## 目标与范围

三名本科生用三台具有 RTX 4060 级显卡的电脑，交付可在局域网运行的软件系统。用户不限制制作周期；质量目标是完整、真实、可复现、有一项可量化的工程改进。

必须形成“本地训练 → 定点编码 → 真实函数加密与证明 → 授权验证与筛选 → 固定批次处理 → 门限聚合 → 更新全局模型”的闭环。演示界面读取真实运行状态。

主要参考是本地 DGFlow.pdf 的 IV–VI 节。没有作者源码时称为“依据论文重建”，不能声称官方复现或完全复现实验结果。

## 系统角色

| 角色 | 职责 | 可以得到的信息 |
|---|---|---|
| 客户端 | 保存自己的数据、训练、量化、加密、生成证明 | 本地数据、本地模型、自己的加密材料、公开全局模型 |
| 密钥节点 | 分布式建钥、按授权生成验证与聚合所需材料 | 自己的主密钥份额、被授权函数及公开上下文 |
| 验证节点 | 检验证明、获得允许的内积、计算相似度、筛选 | 密文、证明、公开范数、授权内积及筛选结果 |
| 聚合节点 | 对批准的密文集合做部分解密 | 密文集合、自己的聚合解密材料、部分结果 |
| 轮次控制与界面 | 管理任务与状态、展示指标 | 公开配置、状态、全局模型、允许公开的实验指标 |

公开范数、授权内积、参与集合和全局模型都是信息泄露边界的一部分；不能说系统“完全不泄露信息”。证明正确不等于模型无投毒或无后门。

## 最小配置与演示配置

- 密码验收：4 个模拟客户端、16 维整数向量、3 个密钥节点、3 个聚合节点。固定批次大小为 2。
- 拟用门限：密钥节点 2/3、聚合节点 2/3。它们是不同机制，须分别实现；具体 DKG 的通信、同步和串谋假设先审阅。
- 正式功能演示：6 个逻辑客户端、3 个固定批次、3 个密钥节点、3 个聚合节点。
- 初始学习任务：MNIST 缩小至 8×8，64 维输入到 10 类的线性分类器，含偏置共 650 个参数。所有这些参数都走密码链路。它是工程起步任务，最终扩大模型须通过性能测量。
- 可扩展任务：原始分辨率 MNIST 小型 CNN；CIFAR-10 或真实分站点业务数据作为后续扩展，不作为初版依赖。
- 统一训练对象为“本轮训练后的完整本地模型参数”，参考向量为上一轮全局模型的同规格量化值。暂不混用梯度或参数差分。
- 与论文一致，批准客户端按等权平均聚合；非批准项权重为 0，批准项为 1。若以后使用样本量加权，必须调整界限、协议规格和所有对照。
- 模型架构、参数展平次序、量化版本、任务、轮次、密钥周期及模型摘要必须一致。

## 协议与工程硬约束

1. 系统中不能设置一个生成完整主密钥再分发的“总钥匙服务器”冒充 DKG。每个客户端可按协议恢复自己的加密材料，但不能得到其他客户端的材料。
2. 每个任务轮次只接受同一客户端的一份不可变提交。重试相同内容返回原状态，换内容或换提交编号也不能造成重复计入。相同密钥、相同加密标签下不得重新提交不同明文；训练重启须进入新的轮次标签或密钥周期。
3. 定点方案须指定范围、尺度、舍入、负数表示、超限拒绝规则，并推导内积、平方和、聚合和的整数上界及群阶条件。合法输入要能在既定预算内完成有界离散对数解码。
4. 零知识证明须证明范数与提交密文内的同一向量一致。签名、哈希和客户端自报范数不能替代它。整数范围如何保证、证明是否绑定实际发放密钥，须由协议规格明确。
5. 论文没有提供可直接调用的完整证明实现。首项工作须补齐所采用证明的具体来源、关系、生成/验证算法、参数、序列化和安全假设，并请老师审阅；不能用一个永远返回 True 的函数填补。
6. 一轮内各客户端使用相同的公共加密标签，由 task_id、round_id、key_epoch、model_hash、quantization_id、维度规范编码得到，以保持论文的共同掩码底数与聚合公式。client_id 通过对应密钥行、认证提交及证明上下文绑定，不能把它直接加入每个客户端的掩码底数而破坏聚合。按论文重建时明确记录与原文标签定义的差别，不能只在 HTTP 外层附加字段而未验证绑定。
7. 各密钥节点独立检查同一轮的参考模型、固定批次和批准密文清单，不接受任意向量函数查询，不对同一轮的不同聚合集合重复授权。控制服务不具备绕过这些限制的权限。
8. 批次在任务内固定。任一成员缺席或被剔除，本轮整批退出；不能为凑人数临时重新分组。需记录被连带剔除的正常客户端数。明确固定批次的客户端串谋边界，不能声称防止所有多轮信息推断。
9. 门限不足、有效批次不足、证明失败、解码越界或密文集合不一致，必须明确中止或拒绝；不能显示一个伪造的成功全局模型。
10. 聚合节点崩溃容错与恶意部分解密容错分开。原协议的集合一致性检查不能自动证明每个部分解密结果正确。
11. 各模式不得将单客户端明文参数写入聚合服务、日志、页面或网络调试记录；明文对照模式除外，且须清楚标识。仅本地离线密码测试可以使用已知明文作断言。
12. 采用经实际验证的研究参数；记录其安全依据。论文中的群名称、参数位数不能直接被包装为现代安全等级。GPU训练时间与CPU密码时间分别测量。

## 分工与模块

- 甲：密码模块、协议规格、密钥节点、证明、编码与解码。乙或丙负责独立核对向量结果与异常输入。
- 乙：数据、本地训练、模型序列化、攻击模拟、四模式实验与指标。
- 丙：公共消息格式、服务、节点身份、状态机、部署、界面与交付脚本。
- 三人共同维护一个仓库、一份接口约定和一份实验配置；每天合并已验收的小功能，不在最后一次性拼接。

依赖方向：协议规格 → 密码核心；训练基线与网络骨架可同时开发 → 接入真实密码 → 鲁棒策略 → 三机部署 → 改进与实验 → 交付。

## 三机局域网部署

| 主机 | 建议进程 |
|---|---|
| A | 客户端1/2、密钥节点1、验证节点1、聚合节点1、轮次控制、界面 |
| B | 客户端3/4、密钥节点2、验证节点2、聚合节点2 |
| C | 客户端5/6、密钥节点3、验证节点3、聚合节点3 |

这些是不同进程；同机角色共享物理故障与管理边界。这个配置用于功能展示，不能宣称等同于独立机构部署。门限演示先停止单个聚合进程；停止 A 整台机器会影响当前控制服务，不承诺自动主控切换。

同一有线局域网优先。先单机独立进程，再通过配置改为三机地址。Linux 环境统一；若用 Windows 上的 WSL2，额外验收从另一台电脑访问服务的能力，不能将 Windows 本地可访问误认为局域网已打通。

## 通信约定

- FastAPI 服务、HTTPX 请求、HTTPS 和独立节点证书；配置客户端证书与信任链核验，不关闭证书验证。
- 小元数据为 JSON；密文、证明和公开模型为有界、可校验的二进制。上传采用 multipart 时 JSON 元数据作为表单文本字段。网络不接受 pickle。
- 上传完成只返回 RECEIVED；密码任务由独立工作进程执行，后续状态由客户端查询。
- 最少接口：获取当前轮次、获取模型、上传提交、查询提交状态、心跳；另外为 DKG、份额发放、授权请求和部分解密定义角色专用接口。
- DKG 广播/私信按选定协议实现。简单 HTTP 群发不是可靠一致广播的证明。
- 业务去重以 task_id/round_id/client_id 为唯一键，并保存提交内容摘要；同一提交号内容改变也拒绝。
- 客户端超时先查询是否收到再决定重传。掉线由轮次截止策略判断，单次 HTTP 超时不立即导致整批退出。
- 界面只通过服务获取状态，不读取客户端数据目录或密钥目录。

## 工程改进与评测

主改进：并行密码计算与可靠提交链路。先采样定位瓶颈，再做任务并行、合规公共预计算、序列化/传输优化以及去重恢复。不得为了快而跳过证明、削弱门限、缩小密钥或缩小解码范围。若测试得不到改善，应如实报告，不能预填百分比。

四模式：A 明文联邦学习；B 加密聚合、无投毒筛选；C 依据论文重建的完整 DGFlow；D C 加团队工程优化。B 是实验消融，明确其关闭项和保证。A/B/C/D 的模型、样本划分、训练超参数和恶意客户端一致；C/D 必须使用相同密码参数与安全步骤。额外保留量化明文结果来分离量化误差与密码错误。

场景：干净 IID、干净非IID、标签翻转、随机/方向反转更新、篡改范数/证明/密文、客户端掉线、聚合进程停止、重复提交。参数扫描分开进行，避免所有因素笛卡尔积。每个主要对照至少 3 个固定种子，正式报告建议 5 个，并报告失败与中止。

指标：全局测试准确率、攻击接受率、诚实客户端误拒率、批次连带退出数、训练与密码各阶段耗时、端到端轮时、实际传输字节、峰值内存、有效完成轮数。攻击者身份仅供离线评测器统计，不能输入检测算法。时间同时记录建钥与预计算的一次性/每轮成本。

## 交付

设计报告、源代码与依赖锁定、启动/复位脚本、测试代码、数据来源和生成配置、实测 CSV/图表、演示视频、用户手册、开源依赖清单。提交设计报告和支持材料匿名，审批签字页单独按要求准备；支持材料控制在截图要求的 4GB 内。离线安装材料若超容量，区分现场运行包与参赛提交包，不漏掉必要复现步骤。

比赛现场显示“当前运行”与“历史实测”标签。加密随机性可能导致两次密文字节不同，不据此判断错误；比较应以验证结果、批准集合和聚合明文输出为准。
