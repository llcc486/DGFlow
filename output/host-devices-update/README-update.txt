DGFlow 各主机独立选择设备更新包

本包为源码更新包，不是网页的部署配置包。适用于当前相同版本的 A、B 源码。
包含此前的共同监控、实验记录同步，以及本次设备选择与 B 本地 GPU 检测修复。

B 更新：
1. 确保没有训练运行。在部署页面释放本机节点，退出本机控制服务。
2. 将本包 src、web 文件夹解压覆盖到 B 的 DGFlow 项目根目录。
3. 保留 B 原有 data、runtime-lan-*、.venv 和本机身份。不要复制 A 的 runtime 或私钥。
4. 重新启动 B 的控制服务和本机节点，刷新网页。仅刷新网页不能更新已经启动的 Python 节点。
5. A、B 在线时先等待上一场实验记录补同步完成，再发起新邀请。

使用：
A 在部署页“本机计算设备”分别选择模型训练 CPU/GPU、密码计算 CPU/GPU，然后发送邀请。
B 在部署页邀请卡片内分别选择本机两种设备，再点击同意。
所有主机同意后 A 开始实验，各主机按自己批准的设备执行。
B 的选择不会从 A 复制；同意后锁定，修改需要退出/重新邀请。
例如 A 用 CPU 训练和 CPU 密码计算，B 用 CPU 训练和 GPU 密码计算，是允许的。
节点监控按实际完成轮次显示 CPU/GPU 训练；实验 JSON 的 client_execution 保存实际训练后端和设备。

环境：
GPU 模型训练要求本机可用的 CUDA 版 PyTorch，CPU 版 PyTorch 不支持 GPU 训练。
GPU 密码计算使用项目 CUDA 密码后端，与 PyTorch 分开检测，不要求安装 CUDA 版 PyTorch。
未通过自检时 GPU 选项不可用；已选择 GPU 后不会静默改用 CPU。
本次本机 PyTorch 未启用 CUDA，因此真实 GPU 模型训练测试跳过，不能把密码 GPU 测试当成模型 GPU 测试。
