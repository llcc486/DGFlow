DGFlow 项目验证报告
日期：2026-10-14

结论
本机验证范围内发现的功能回归已修复，当前没有未处理的测试失败。
各主机可分别批准自己的模型训练设备和密码计算设备，A 不能替 B 覆盖选择。
但目前不能认定 A/B 现场升级后的完整流程已验收：B 仍运行旧代码，记录同步仍返回 B: ValueError。

验证结果（保留真实的全量运行与复测区别）
1. 完整后端环境：全量 3977 项通过、1 项失败、31 项跳过。
   唯一失败为旧测试未包含新增 training_execution 字段；修正后该文件 4 项全部通过。
   合并全量结果与复测，3978 项覆盖通过，31 项条件跳过；没有把原始失败日志改成成功。
2. 干净基础环境：全量 3586 项通过、同一项断言失败、348 项跳过。
   修正后该文件 4 项全部通过，合并覆盖为 3587 项通过。
   基础环境没有安装 Torch、Rust 扩展及 GPU 可选依赖，因此相关测试按条件跳过。
3. Rust 扩展使用 Cargo.lock 从源码构建成功；新 wheel 安装至干净环境后，253 项密码、邀请和控制服务测试全部通过，无跳过。
4. 前端在独立目录执行 npm ci，338 项测试全部通过，生产构建通过。
5. CPU 训练专用检查：568 项通过，4 项真实符号链接测试因 Windows 权限不足跳过。
   严格 CI 门禁因此返回失败；没有放宽门禁，也没有宣称 Linux CPU CI 已通过。
6. Ruff 代码检查、源码身份信息扫描、源码打包及 SHA-256 校验通过，交付源码包包含 574 个文件。
7. 真实浏览器加载生产前端：选择设备、同意邀请、自动跳转监控、隐藏卡片、刷新保留记录和移动布局检查通过。
   这些交互使用隔离 API 场景，并非对 B 真实页面的远程操作。A 当前在线页面另行检查，JavaScript 错误为 0。
8. 隔离多机集成测试实际执行认证通信、同意后开训、模型训练、证明与聚合、记录同步，以及 A CPU/B GPU 密码计算。
   隔离主机运行于同一台物理电脑，不代替两台电脑升级后的现场测试。

本轮验证修复
- 修复单机/嵌入式节点读取设备设置时误要求 LAN 地址元数据的回归，保留旧单机训练路径。
- 修复 LAN 控制服务启动时，GPU 自检抢先阻止启动本机节点的竞态；运行中、已批准邀请、修改部署等保护仍保留。
- 更新实际训练设备证据的测试契约；将真实 CUDA 模型测试移出 CPU 必跑目录，保持严格 CPU 门禁。
- 修复测试收集路径断言，使用项目外短临时目录避免 Windows 路径长度限制干扰验证。
- 在项目虚拟环境内补齐 python-multipart 版本要求，没有修改全局应用依赖。
- 更新历史论文实验的版本差异记录；历史实验仍明确标注为对应旧源码，未冒充当前版本的新验收。

当前现场状态及尚未验证的范围
- A 的 3 个本地控制服务和双机实验的 7 个 A 节点已加载新代码；没有正在运行的训练。
- A/B 共 13 个节点均响应认证健康检查。A 的 7 个节点支持新设备选择协议；B 的 6 个节点尚未支持。
- B 仍需安装同目录提供的更新包并重新启动控制服务、节点；仅刷新浏览器无效。
- 上一场实验本地记录同步仍提示“实验记录同步等待重试：B: ValueError”，不能视为已完成同步。
- 当前 PyTorch 为 CPU 版本，真实 GPU 模型训练尚未验证。GPU 密码计算已验证，不等于模型训练 GPU 已验证。
- 31 项完整后端跳过项：16 项原生 Unix Bash，8 项符号链接权限，6 项不适用的数据格式组合，1 项真实 CUDA 模型训练。
- Linux、Python 3.11 的 CI 矩阵尚未在本次 Windows 环境执行。
- 原 .venv 继承全局包，pip check 仍存在其他软件的依赖冲突；新建的隔离环境安装、pip check 均通过。
